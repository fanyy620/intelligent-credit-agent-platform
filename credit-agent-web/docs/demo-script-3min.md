# 悬浮智能助手 · 3 分钟面试演示脚本

> 适用场景：现场可联网、演示机已配好 KIMI_API_KEY。
> 设计原则：**LLM 的等待时间就是讲解时间**——每一步的延迟都经过实测（查客户 23s / 看数据 15s / 推荐 80s / 文案约 100s），脚本把等待窗口全部填上讲点，不冷场。
> 账号：`admin / 123456`

---

## 演前 2 分钟准备（面试官到场前完成）

- [ ] 三服务已起（`npm run dev` 一键拉起 前端+业务后端+Agent）
- [ ] 已登录，停在「数据看板」页，悬浮气泡在右下角可见
- [ ] **预热**：点开悬浮窗发一条"你好"并等回复返回（激活 LLM 网关，避免正式演示首轮冷启动）
- [ ] 浏览器只留这一个标签页，字体放大到 110%（投影可见）

**应急预案**（心里记住，不用讲）：
- LLM 超时 → 界面会出降级回复，顺势说："这正是工程化设计的一部分——模型不可达时系统降级到本地规则管线，业务不中断"，反而加分
- 动作识别偏差 → "所有动作都在白名单内，识别错了也不会执行危险操作，这是三道安全闸的意义"

## 正片（总时长 3:00）

### 0:00–0:15 ｜ 开场定调

**🗣 演示话术**：
> "这是一个南洋商业银行对公信贷场景的智能中台。传统银行系统是'人找功能'，我做的是'功能找人'——客户经理用一句话就能调度整个系统。您看右下角这个悬浮助手，我们直接演示。"

**🖥 页面反应**：鼠标移向右下角红色气泡，点击展开「南洋智能助手」面板。

**🎯 埋点**（不说破）：让面试官注意到这是全局悬浮窗，任何页面都能唤起。

---

### 0:15–0:40 ｜ 第一步：模糊查客户

**🗣 演示话术**（边输入边说）：
> "比如我记不清客户全名，只记得姓华——'**帮我看看华创那家公司最近的情况**'。"

**🖥 页面反应**（约 23 秒，这段时间讲话）：
助手回复 → **页面自动跳转到企业客户页 → 模糊匹配"华创精密制造有限公司"→ 弹出客户详情卡片**，消息流里给出回执"已为您打开华创精密制造有限公司的详情"。

**🎯 技术点讲解**（在等待的 23 秒里讲完）：
> "这句话有三个模糊点：'华创'不是全称、'那家公司'是指代、'最近的情况'没有指明查什么字段。大模型通过提示词把它翻译成一个结构化动作指令 `view_customer{华创}`，前端校验后执行。这里有三道安全闸：提示词约束输出格式、Agent 端白名单校验、前端执行前再校验一次——**模型只能提议动作，能不能执行由代码说了算**。"

---

### 0:40–1:00 ｜ 第二步：口语化问经营数据

**🗣 演示话术**：
> "再口语化一点——'**最近业务数据怎么样**'。"

**🖥 页面反应**（约 15 秒）：悬浮窗内直接渲染 2×2 迷你统计卡（今日咨询、推荐笔数、合规通过率、意图分布），无需跳页。

**🎯 技术点讲解**：
> "'最近''怎么样'都是模糊语义，模型结合当前页面上下文判断这是看板查询意图，返回 `show_stats` 动作。数据来自 SSM 业务后端的 MySQL 聚合——**大模型负责理解，业务系统负责算数**，职责是分开的。"

---

### 1:00–2:25 ｜ 第三步：完整的对公授信推荐（核心戏）

**🗣 演示话术**：
> "现在是核心业务。客户经理拿到一个需求——'**我们是制造业企业，需要 200 万流动资金周转一年，推荐下**'。"

**🖥 页面反应**（约 80 秒——这是全场最长的等待，也是最大的讲解窗口）：回复返回真实推荐：Top1 税易贷（综合分 0.614）、Top2 安居房抵贷（0.613），各带额度/利率/期限/审批时效四维评分条和推荐理由。

**🎯 技术点讲解**（80 秒从容讲，这是脚本里最重要的 80 秒）：
> "这句话进来之后走了五层：第一，**意图识别**——除了提示词方案，我还用 1000 条真实业务对话通过 LLaMA-Factory 做了 LoRA 微调，把意图准确率从 Prompt 基线的 70% 提到 85% 以上；第二，**槽位抽取**——金额 200 万、期限 12 个月、用途经营、行业制造业，大模型能把'制造业'补全成'企业主'身份，这是规则词典做不到的；第三，**三层推荐架构**——先规则过滤硬性准入，再 RAG 语义召回，最后按额度、期限、利率、审批速度四维加权打分重排；第四，**记忆**——Redis 短期会话 + PGVector 长期事实，下一轮它还记得这个客户；第五，**防幻觉**——您看推荐理由里没有一个数字是大模型编的，所有数值都来自结构化产品库，这是我从审计合规背景带来的设计洁癖。"

**💡 彩蛋操作**（讲解完立即做，不发一言）：在悬浮窗输入"**顺便把税易贷写成朋友圈文案发我**"，回车后继续下一步——文案在后台异步生成，不阻塞。

---

### 2:20–2:45 ｜ 第四步：合规拦截（即时响应，调节奏）

**🗣 演示话术**：
> "银行场景合规是红线。我故意发一段违规话术——'**这款产品保本保息，百分百下款，无视黑白户**'。"

**🖥 页面反应**（即时，无 LLM 延迟）：正则闸秒级拦截，违规词红色高亮，提示命中规则明细。

**🎯 技术点讲解**：
> "双重风控：第一道正则词库秒级拦截硬违规；第二道语义审核拦截变相承诺。而且审核策略分场景——营销文案宁严勿宽，对话回复复核失败默认放行。**合规通过率超过 90%**。"

---

### 2:45–3:00 ｜ 收尾（弹性：文案彩蛋）

**若文案已返回**（大概率刚好回来）：
> "刚才那句'顺便写文案'有结果了——您看成稿：额度 300 万、利率 3.85% 全部来自产品库后填充，大模型只写文案骨架、碰不到数字，从根上杜绝数值幻觉。"

**🗣 收尾话术**：
> "总结一下：前端 Vue + Element UI，业务层是经典 SSM + Redis，智能层是 Python Agent——提示词工程做理解与表达，确定性代码做计算与安全。三层各司其职，这是我认为企业级 Agent 落地的关键。谢谢。"

**🖥 页面反应**：停在悬浮窗展示文案成稿+合规通过标签的画面。

## 超时保险（如果被打断或时间充裕）

| 情况 | 应对 |
|---|---|
| 面试官中途提问技术细节 | 正好跳过第四步，直接答问；第三步的 80 秒讲解是弹性最大的部分 |
| 时间充裕（给到 5 分钟） | 加演：追问"那它呢"展示指代消解与记忆；打开推荐记录页展示落库 JSON；展示 war 包与 Langfuse trace |
| 网络完全挂了 | 切离线 Mock 模式演示（`dev-all` 默认降级），明说"这是无网络降级管线"，动作功能依然可用 |

## 全程技术点索引（面试官追问时快速对号）

语义动作 → 第 7 层 SITE_ACTION_PROMPT + 白名单三闸｜意图 → LoRA 微调（70%→85%）｜推荐 → 槽位抽取–规则+RAG召回–LLM重排｜记忆 → Redis+PGVector 分层｜合规 → 正则+语义双闸、分场景策略｜防幻觉 → 模板+数据后填充｜工程 → SSM 编译 war、Langfuse 全链路观测、全链路优雅降级
